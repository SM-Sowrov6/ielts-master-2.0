## 1. Principles

1. **Semantic tokens only.** Components use `bg-background`, `text-muted-foreground`, `border-input`, … and never raw colours (`DEVELOPMENT_GUIDELINES.md` §3).
2. **Accessible by default.** WCAG 2.2 AA: contrast is verified per token pair, every interactive pattern has a keyboard path, and landmarks plus a skip link exist in every shell.
3. **Primitives + patterns, no premature features.** `components/ui` holds shadcn/ui primitives (no domain logic). `components/patterns` holds composed, reusable UI. Feature code arrives in `src/features/<domain>` in later phases.
4. **Brand palette decided (2026-11-18):** Royal Blue `#2563EB` (primary, derived from `--brand-hue: 263`) and Emerald `#10B981` (`--brand-accent`), on cool slate neutrals. Font: **Geist only** (no Inter, by decision). The wordmark is still plain text until a logo exists.

## 3. Tokens (`src/app/globals.css`)

**Colour.** Semantic pairs for both themes: `background/foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, plus the additions `success`, `warning`, `info`, `border`, `input`, `ring`, `surface` (section band, slate-50), `brand-accent`, `chart-1…5`, and `sidebar-*`.

| Brand token | Light | Use |
|---|---|---|
| `--primary` | `#2563EB` (oklch 0.546 0.215 263) | Actions, links, focus ring, key metrics. 5.17:1 on white |
| `--brand-accent` | `#10B981` | **Decorative only** (fills, bars, glows). It is 2.5:1 on white, so never text or a meaningful icon |
| `--success` | `#047857`-equivalent | Success *text* (5.37:1). The emerald family's accessible text shade |
| `--foreground` / `--border` / `--surface` | `#0F172A` / `#E2E8F0` / `#F8FAFC` | Slate neutrals from the reference |
| `--muted-foreground` | slate, oklch 0.5 | Darker than the reference's `#64748B`, which fails 4.5:1 on slate-100 |

| Rule | Check |
|---|---|
| Body and muted text ≥ 4.5:1 on every surface it appears on | `scripts/check_contrast.py` |
| Input boundaries and focus ring ≥ 3:1 (WCAG 1.4.11) | `scripts/check_contrast.py` |
| Contrast is re-checked whenever a token or `--brand-hue` changes | CI (`frontend` job) |

The checker reads the real CSS (`:root` and `.dark`) and checks 28 pairs per theme (surface, accent and card pairs added 2026-11-18). Current result: 0 failures. Stock shadcn neutrals failed muted text on muted backgrounds and input borders, so those tokens were adjusted.

**Typography.** `--font-sans` (Geist), `--font-mono`, and `--font-heading` (currently the sans). The type scale is Tailwind's (`text-xs` … `text-3xl`). Everything is in `rem`, so browser text size and zoom scale the whole UI (WCAG 1.4.4, NFR "adjustable text size").

**Spacing & layout.** Tailwind's 0.25rem scale, plus `--spacing-header` (3.5rem), `--spacing-sidebar` (16rem), `--container-content` (72rem), `--container-prose` (42rem).

**Breakpoints.** Tailwind defaults: `sm` 40rem · `md` 48rem · `lg` 64rem (sidebar ↔ drawer switch) · `xl` 80rem · `2xl` 96rem.

**Radius / elevation / motion.** `--radius` (0.5rem, 8px cards) with a derived scale; elevation utilities `shadow-elevation-1` (cards), `-2` (hover/focus), `-3` (overlays), `-float` (3D layers), with stronger dark-theme values; z-layers `--z-index-header` (40) and `--z-index-overlay` (50), and durations `--duration-fast` / `--duration-base`. A global `prefers-reduced-motion: reduce` rule neutralises animations and transitions.

**Focus.** Components use their shadcn focus styles. A global `:focus-visible` outline (2px `--ring`) covers anything else.

## 5. API client conventions

- **Source of truth:** backend OpenAPI. `uv run python scripts/export_openapi.py` → `frontend/src/lib/api/openapi.json` → `pnpm api:generate` → `src/lib/api/schema.d.ts`. Both are generated; CI job `api-contract` fails on drift.
- `browserApi` (relative, same-origin) for Client Components. `serverApi()` (`API_INTERNAL_URL`) for Server Components. In development, `next.config.ts` rewrites `/api/*` to the backend, exactly as Nginx does in production (ADR-006). Production builds contain no rewrite.
- Errors: `unwrap()` turns a non-2xx result into `ApiError { status, code, requestId, fieldErrors }` parsed from problem+json. UI code branches on `code`, never on message text, and never displays raw error text.
- **Deviation from `API_SPECIFICATION.md` §1:** runtime **Zod schemas are not generated** from OpenAPI yet. Forms use hand-written Zod schemas for UX validation (the server validates authoritatively). Generating Zod is decided when the first form binds to a real API (Phase 5/6).

## 6. Server-state conventions (TanStack Query)

- One `QueryClient` per browser session (`Providers`). Defaults: `staleTime` 30 s, no refetch on focus, **no retries for 4xx** (`ApiError.isClientError`), up to 2 retries for network/5xx, and **no mutation retries** (non-idempotent unless the API uses `Idempotency-Key`).
- Query keys come from `src/lib/query/keys.ts`: `queryKeys.<domain>.all` is the invalidation root, and narrower keys extend it.
- Initial page data is fetched in Server Components. TanStack Query is for client-side interaction, mutations and live data (`DEVELOPMENT_GUIDELINES.md` §3).

## 7. Patterns (`src/components/patterns`)

| Pattern | Contract |
|---|---|
| `PageHeader` | The page's single `<h1>`, optional description and actions |
| `EmptyState` / `ErrorState` / `LoadingState` | Error uses `role="alert"`. Loading exposes one `role="status"` message with skeletons `aria-hidden`. The heading level is configurable |
| `DataTable` | Presentational. Required caption (accessible name), `scope="col"` headers, optional row header, horizontal scroll on small screens, empty state instead of an empty table. Sorting and pagination state belong to the caller (URL / Query) |
| `ConfirmDialog` | Radix Dialog: focus trapped, Esc cancels, focus returns to the trigger, async confirm keeps the dialog open with buttons disabled |
| `FormTextField` | RHF `Controller` + shadcn `field`. Label `htmlFor`, `aria-describedby` for description and error, `aria-invalid`, error as `role="alert"` |
| `ComingSoon` | Placeholder for routes delivered in later phases |

## 9. Adding or changing UI

1. Need a primitive? `pnpm dlx shadcn@4.23.0 add <name>`, review the generated file, then `pnpm format`.
2. Compose primitives into a pattern (with tests and an axe check) before reusing UI in two features.
3. Changing a token or `--brand-hue`? Run `python -I scripts/check_contrast.py`.
4. Never pass functions (icons, callbacks) from a Server Component to a Client Component. Pass serialisable keys instead.
